# 前两个领域技能修订交接

日期：2026-09-10。domain-knowledge 与 domain-model 已更新为0.3.0，使用平台无关领域合同2.0.0。semantic-foundry 保留可选入口，未恢复任何生产技能对它的依赖。

## 已实现

知识形成、确认和争议分别记录；来源、陈述、术语、规则、案例与冲突引用均有类型及存在性检查。问题的四类案例覆盖、不适用与缺口明确登记。

领域模型把身份、时间、状态、事件、度量、证据和未知政策绑定到具体要素。判断按给定输入、规则、条件、顺序步骤和输出描述；新增检查覆盖关系端点、属性归属、语义依据、基数、循环、问题范围、步骤依赖与案例预期一致性。

创建、审查、修订分别约束。已有未确认知识或模型可直接进入 REVIEW，交付审查报告和发现；创建或修订模型仍核对知识确认。用户不需要先填 JSON，技能负责整理引用并交付业务审查稿。两包均有设备维护的合成教学例子，不将其作为客户事实或实际业务验证。

## 最小接收同步

ecp-semantic-authoring 0.2.1 随包接收模型2.0.0合同副本与其公共对象；自身平台资产合同保持1.0.0，Mapping 和 Release 无需同步升级。Registry 中两个命名空间管理不同阶段，不是对旧模型的兼容回退，旧模型版本会被拒绝。

semantic-foundry 0.5.2 的仓库校验可同时检查这些精确版本。单阶段校验通过 --skill 显式选择并调用技能自身入口，避免 REVIEW 输入形状相同时猜测阶段，也避免编排器维护第二套业务校验逻辑。各技能仍单独安装和使用。

## 实际证据

在只有一个技能的临时父目录中分别核对两个领域技能及编制技能。三份包结构与 Schema 检查、51项固定资源摘要、96个本地文档链接、三个 CLI 入口均通过；两个领域技能和编排脚本共5个 Python 文件 AST 通过。编排器13份 Schema 和24项原始资料检查通过；git diff --check 通过。详见 [检查记录](domain-foundation-checks.json)。

qiaomu 包检查没有 failure；保留中文 README 启发式、缺少触发评估及内部辅助模块等 warning。领域两包中没有 ECP 平台状态或执行依赖；原始方法手册按范围引用，未篡改源文件。

这些检查没有执行实际业务交接案例、新旧版本行为回归、模型触发或生成评估、领域专家审查、宿主安装、平台编译或运行。没有新增或修改测试代码，没有运行既有测试套件。工具实现不等于业务质量已验证，技能保持 scaffold candidate。

本次继续采用已研究的 qiaomu-meta-skill、OntologyEX 与 ontology-agent-suite 的合同、能力问题和审阅证据方法。修订针对既有五项缺陷，不新增法规判定、平台规则或新的编排体系。
