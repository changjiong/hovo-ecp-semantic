# 澄清、访谈与确认

依据：02 §3.6 与 §4.4。让用户判断真正影响业务的事项，使答复能够落实到资产。

## 当前生成任务

默认最多 1 轮、最多 5 个高影响问题。先读取材料，处理可查事实和可逆设计；只对影响含义、事实采用、结果或执行的未知提问。每题给推荐、依据、替代方案、影响和不答时处理。只有明确请求Workshop（研讨）或明确请求 Workshop 才持续多轮访谈。

| 类别 | 依据与处理 |
| --- | --- |
| `CONFIRMED` | 可定位证据或责任人明确确认，标明是哪一种 |
| `INFERRED` | 可从已知材料推导，说明前提与依据，不假称用户确认 |
| `ASSUMED` | 低风险可逆设计，说明适用范围和变更影响 |
| `OPEN` | 高影响业务分歧待裁定，给推荐及所需确认人 |
| `BLOCKED` | 缺必要资料、平台能力或授权，依赖步骤不能完成 |

真实字段、法定阈值、客户事实、采信和批准不得归入可逆假设。材料重复出现说法不自动证明真实性。可疑同一性不得自动合并。

预算耗尽后只阻塞依赖资产，继续所有无需该输入的部分。用户沉默不构成同意。缺平台运行条件时继续完成设计与可检查资产，分别保留技术运行与业务确认缺口。

## 后续需求访谈

有限澄清与后续实施访谈不同。完整确认清单随业务审查稿交付，可按业务、数据、平台、使用者分组，不限五条；无需现在逐项要求用户回答。

每项用稳定 ID 记录：待确认陈述、现有证据、推荐及理由、可选口径、影响的问题/概念/字段/规则、责任角色、所需材料、未确认前处理。答复后记录原答复定位、确认人和角色、日期、采用口径、适用范围/版本和异议；未经明确答复不得填写签字或确认时间。

确认围绕具体例子，例如“该比例指所有权还是表决权”“缺比例的来源可展示，但是否可计算”。避免要求业务人员批准 OWL 关键字或编译器 JSON。

## 确认后的回写

按事项 ID 定位业务陈述、IRI、映射、约束、规则、Scope、案例和证据。修改后重算相关摘要，按授权重验；旧修订证据仍归档，不转用于新修订。共享概念按其所有者和发布流程处理，不因一次场景确认直接改公共资产。

业务负责人确认定义或验收口径；数据负责人确认字段与覆盖；平台证据证明导入编译；业务审批者决定正式采纳。作者自检不写成独立专家审查，技术结果不代替业务签认。
