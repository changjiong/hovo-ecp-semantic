# 从材料和数据结构确定输入

依据：00 §4、01 §4 与 §6、02 §2-3 与 §5.4。只收集当前能力问题需要的信息；不存在字段、访问授权或业务解释时保持缺口。

## 读取现有输入

| 输入 | 应提取的证据 | 缺失时继续什么 |
| --- | --- | --- |
| 业务材料、制度、流程或案例 | 文件/版本/页码或段落；任务、定义、适用条件、例外、结果用途、确认责任 | 形成候选问题及待确认含义，不依据表名发明规则 |
| DDL、数据字典、JSON Schema 或接口模式 | 来源、采集日期、结构、字段、类型、可空性、主键、唯一性、关系依据 | 可做概念和合成说明；真实 Mapping 阻塞 |
| 已授权样本 | 记录定位、脱敏方式、空值/重复/异常、时间及数值实际表示 | 可按 schema 设计，转换和数据质量证据未执行 |
| 已有领域资产 | 精确版本、定义、IRI、身份、用途、Profile、所有者、已知限制 | 新增当前切片所需概念，不预建公共层 |
| 目标 ECP 信息 | Profile ID/digest、包版本、数据源目录与 sourceBindings、可用算子、编译预期来源 | 使用随包 Kit 设计候选，目标平台匹配与运行未验证 |

每项输入保留材料身份和定位，不复制连接凭证。用户提供的 DDL 是模式证据，不自动证明与 live schema 一致；有任务授权和实际连接能力才核验线上结构。表注释和已有 SQL 是理解线索，不自动成为业务定义。

## 字段落实

业务审查稿记录当前问题的字段对应：`来源/表.字段 → 记录粒度和键 → 目标 IRI/属性 → 转换及单位 → 缺失和异常处理 → 使用的问题 ID → 依据与确认状态`。

- 记录主键标识来源行、业务对象还是版本；现实对象身份来自哪个可核实标识，发放范围是什么。
- 多表关系由外键、经确认的键合同或已验证映射支持；同名、格式相似、样本恰好相等都不足以证明 join。
- 数值单位、尺度、分母、精度和舍入；日期粒度、时区、有效期与知识截止；枚举值及未知值处理。
- 可空字段在来源保存、计算输入和业务判断阶段怎样处理。没有观测值不能补成零、false、长期有效或已确认。
- 计算、跨源归并和事实采用由哪里执行。Mapping 不支持的表达不能塞进自造字段或字符串脚本。

结构没有明确 dataSourceId、sourceCode、批次或运行绑定时，可以完成字段语义设计，但不得把占位符登记为真实可运行映射。敏感连接配置由平台目录管理。

## 事实采用与覆盖

权威单源且已有数据治理合同的场景，可引用合同及责任人、时效、异常策略和来源定位，无需逐行添加人工采信对象。多源争议、文档抽取或客户申报需区分原始记录、断言、采用/排除依据和消费者读取的任务事实。

分别说明来源读取、映射字段/关系、任务事实集合的覆盖。扫描完一张表不等于现实业务完整。截断、行错误、身份未解析和未知关系必须传递到结果完整性说明。

## 缺口变成确认议题

区分材料不足、业务含义待定、数据不可提供、平台能力未证实、执行授权未获得。每项给受影响的问题/资产、最小补充资料、责任角色和补齐之前能交付的内容。

业务访谈可以确认口径，不能凭口头通过证明数据库存在字段；数据负责人可以确认字段含义，不能因此批准最终业务结论。
