# 模式、替代方案与反例

依据：01 §5-7、02 §4、03 的有限所有权样板。领域模型选择取决于确认的业务问题、规则与案例，不以物理数据结构或类数量决定形状。数据可用性在映射阶段形成反馈，不直接改变业务定义。

| 情形 | 推荐决定 | 必查反例 |
| --- | --- | --- |
| 简单二元关系 | 使用有方向的属性 | 关系反向后含义是否改变 |
| 业务固有属性 | 定义业务含义、归属、类型、单位、合法值与未知 | 更换系统后名称与定义是否仍成立 |
| 来源字段和 ETL 元数据 | 留在映射、治理来源和证据载荷 | 是否把原值格式当成了主体属性 |
| 关系有比例、时段、权利类型、多参与者或独立引用 | 评估关系对象并明确身份 | 增加第二份证据是否误增业务对象 |
| 主体承担股东、借款人、审批人等职责 | 上下文角色或有明确上下文的类 | 职责终止后是否仍为永久本质类型 |
| 业务事件与状态 | 区分变化事件、结果状态和获知事件 | 无事件记录是否被当成状态没变化 |
| 单一治理来源 | 复用数据服务的采用合同与来源责任 | 过期、缺失、异常来源是否继续被消费 |
| 多源争议或文档抽取 | 原始记录、断言、采用依据、任务事实分开 | 最高置信度、最新或多数是否未经确认被当权威 |
| 同名与身份匹配 | 明确标识发放范围及身份依据 | 同名不同人、同人更名、重复导入 |
| 历史与追溯更正 | 区分有效时间和知识截止，保留原输入 | 新材料是否改写当时所知结果 |
| 数量与比例 | 明确单位、尺度、分母和舍入 | 0、缺失、25 和 0.25 是否混同 |
| 局部图与路径计算 | 明确算法前提、遍历完整性和资源限制 | 环、缺边、截断是否仍给确定结论 |
| 候选与正式判断 | 区分输出类型及权威记录 | 规则命中是否跳过核实与批准 |

平台化时保留业务承诺，只有确认 ECP 支持的表达才进入导入包。OWL 中不同 IRI 不自动证明对象不同；domain/range 的类型含义不等于数据完整性检查；开放世界下缺事实不等于否定事实。

所有权模式不硬套到其他领域。贷后事件关注发生时间、影响对象和信号依据；交易对账关注账务口径、金额、币种和差异；供应链依赖关注方向、层级、替代与覆盖。可以复用稳定主体和来源概念，不必都创建权益对象或逐行采信流程。
