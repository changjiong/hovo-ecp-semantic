# 从领域知识到业务领域模型

## 1. 领域模型的边界

Domain Knowledge（领域知识）回答“业务是什么、为什么、怎么判断”。

Domain Model（领域模型）回答：

- 这个业务世界有哪些稳定对象？
- 对象之间有哪些稳定关系？
- 哪些事实和时间必须被保留？
- 基于这些事实有哪些稳定业务判断？

领域模型不是第二份知识说明书，也不是 Workflow（工作流）、Policy（机构政策）、Database Model（数据库模型）或 ECP（可执行语义协议）执行资产。

## 2. Rule 先审范围，再建模

每条 Knowledge Rule（知识规则）先分类：

- `CORE_STRUCTURE`：揭示核心结构；
- `DOMAIN_DECISION`：揭示领域判断；
- `EXTERNAL_CONTEXT`：引用邻接领域；
- `NO_MODEL_CHANGE`：不需要改变模型。

一条规则可以同时属于 `CORE_STRUCTURE` 与 `DOMAIN_DECISION`。

完整性不是“每条规则都生成模型元素”，而是“每条规则都被正确处理”。

## 3. 怎么识别稳定业务结构

先写实例句，再决定是否建模。

只有在业务中具有独立身份、生命周期、稳定关系语义或必须被单独引用时，才独立建模。

优先识别：

- Entity（实体）：自然人、组织、产品等；
- Role（角色）：法定代表人、受托人、管理人等；
- Fact / Relation（事实/关系）：股权、收益权、控制、隶属等；
- Arrangement（安排）：代持、表决权委托、一致行动等；
- Evidence（证据）：支撑身份、关系和时间；
- Event / Temporal（事件/时间）：关系形成、变更、终止。

阈值、标签、规则编号、审批动作和实现中间量通常不是对象。

## 4. 怎么识别领域判断

稳定领域判断回答：

> 已有事实在业务上意味着什么？

例如：

- 最终拥有比例达到阈值 → 标准一判断；
- 收益权/表决权达到阈值 → 标准二判断；
- 控制事实是否构成实际控制 → 标准三判断；
- 前三项均明确不存在 → 兜底资格；
- 主体性质 + 风险事实 → 简化资格。

确定、跨实现长期稳定的判断可以用 DSL Rule（DSL规则）。

只有确实需要专业人员对证据效力、冲突和业务责任做裁定时，才使用 Judgment（人工判断）。

## 5. Knowledge 5.0.0 字段怎样参与建模

- `business_conclusion`：帮助识别 Rule 的业务结果；
- `required_facts`：寻找模型必须表达的事实、关系和字段；
- `decision_steps`：用于理解判断依赖，不自动生成 Process；
- `evidence_requirements`：寻找 Evidence 及其支持关系；
- `non_sufficient_facts`：进入判断约束，防止弱线索直接推导结论；
- `unknown_behavior`：决定 UNKNOWN 如何传播或阻断；
- `human_boundary`：判断是否存在真正的 Judgment；
- `case_ids`：用于反向验证，不生成第二套案例真值。

## 6. 外部上下文怎么处理

Rule 提到一个概念，不代表它必须进入本领域核心模型。

问：

> 去掉这个概念后，我还能否完整表达本领域“谁/什么、有什么关系、什么时候有效、依据什么、得到什么判断”？

如果可以，只保留最小上下文。

例如历史 UBO 只需要判断时点，而不需要完整交易模型；AML（反洗钱）风险结果可以作为输入，而不需要在 UBO 模型里重建 AML 风险体系。

## 7. Process 和 StateMachine 是可选项

Process（流程）和 StateMachine（状态机）只有在它们本身属于稳定业务事实时才建模。

“为了让模型看起来完整”“为了串起规则”“为了本地执行”都不是创建它们的理由。

## 8. Coverage 的正确语义

Rule Coverage（规则覆盖）不是“规则是否被翻译成模型”。

它记录：

- 规则揭示了什么模型意义；
- 是否产生核心结构；
- 是否产生领域判断；
- 是否只是外部上下文；
- 是否无需改变模型；
- 若已建模，具体由哪些模型元素承接；
- 若未决，缺口在哪里。

允许正确的零模型映射。

## 9. Case 与 OPEN

Case（案例）只验证模型是否能够表达上游已确认事实和结果，不重新解释案例。

OPEN（未决）不能在建模时被默认值关闭。若 OPEN 只影响外部上下文，也要说明其对核心模型是否有影响。

## 10. 最小性原则

好的领域模型不是元素越多越完整，而是：

> 用尽可能少的稳定结构和判断，无损表达尽可能多的业务知识。
