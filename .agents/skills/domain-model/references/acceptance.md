- [ ] 精确输入引用、摘要、知识依据和模式通过；FULL_BASELINE范围等于知识全部问题。
- [ ] 每个对象名称有来源、具体业务句子、正反例和独立理由；身份解释能够区分现实实例。
- [ ] 人/组织/对象、关系、判断、证据、时间连通；角色承担者、Ref目标和基数明确。
- [ ] 全部知识规则七要素逐项对应；条件关联真实表达式或人工准则，例外与缺证行为未遗漏。
- [ ] DSL2语法、输入输出绑定、结果类型、依赖无环、流程读写、状态守卫和时间含义通过检查。
- [ ] 固有人工判断具有完整准则与责任；未决口径和语言能力缺口分别记录，不互相替代。
- [ ] 全部问题、关联规则、原始案例和OPEN事项均有处理；案例input_facts/expected/forbidden未改写。
- [ ] 案例逐步解释与实际执行状态分开；执行声明能追溯具体输入、结果、模型摘要和证据。
- [ ] review.md采用业务语言，coverage.md保留完整技术矩阵，均从相同DSL确定生成且字节一致。
- [ ] 修订前旧版模型、请求、审阅稿、覆盖表、交接和原反馈已归档；当前目录只有一个清晰入口。
- [ ] 结构、求值、语义审查、业务评审、正式确认分别记录；不凭PASS制造确认。
- [ ] qiaomu输出评估覆盖本轮失败：抽象难懂名称、遗漏对象端点、通用id身份、局部充全量、仅挂引用、人工裁定误判缺口。
- [ ] 另一无关领域也验证机制适用性；仅语法示例不能宣称泛化质量已证实。
- [ ] 技能、规范、Schema、脚本、样例、接口和报告版本一致。下游未支持DSL2时不声称平台交接完成。
