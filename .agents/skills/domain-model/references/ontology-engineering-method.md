# 从业务问题到可审查模型

依据：00 §2-3、01 §3-6、02 §4。先做一个能解释并能核对的任务，再沿相同含义扩展。

## 能力问题与认知机理

每个能力问题具有稳定 ID，固定使用者、输入、时点、政策、事实集合、覆盖、执行责任、精确预期、禁止结果与不足处理。查询、语义推论、确定性计算、业务规则和人工判断分别注明；本体提供概念基础，不承担所有执行责任。

1. **目标**：用户要作什么判断，结果以什么形式供谁使用。
2. **事实**：采用什么来源、对象、时点和范围，为什么可用；排除什么，仍未知什么。
3. **事理**：依据哪条定义、算法、条件、参数或例外得到结果；前提不满足时怎样停止或降级表达。
4. **判断**：输出是来源报告、计算量、线索、分支候选还是正式认定；包含哪些依据与限制。
5. **行动**：由谁补证、复核、确认或执行；实际由哪个系统承担，权限何在。

对每条计算或判断给简短推导示例，列输入、领域规则、中间业务量和结果。展示可复核的方法与证据，不索取或输出模型私有思维过程，不拿自动生成的长解释当真实性证据。

## 六项概念检查

| 检查 | 需要形成的业务承诺 | 常见退回原因 |
| --- | --- | --- |
| 定义 | 中文名、定义、正例、相邻非同义概念 | 表名换成英文类名；同名就强行合并 |
| 粒度 | 一个实例具体是什么 | 现实对象、文档、来源行、一次判断混为一体 |
| 身份与变化 | 什么变化保持对象，什么变化产生新对象/版本 | 更名即新主体；换人仍沿用同一人员标识 |
| 参与关系 | 起点、终点、方向、参与者、上下文和基数 | 用 is-a 表示任职、组成或来源 |
| 时间与计量 | 有效时点、知识截止、单位、尺度、分母、精度 | 百分数和小数混用；未知终止日即永久有效 |
| 消费与反例 | 哪个问题使用，允许和禁止哪些推论 | 有数据即有事实；事实即批准；缺失即否定 |

概念卡放在业务审查稿，以稳定概念 ID 定位。重要分叉用“需求、候选方案、选择、依据、后果、反例”记录，并在成果确认前裁定，普通命名直接采用本地惯例。

## 对照业务知识

通过 knowledge_ref 回到对应业务陈述、术语与规则，核对含义、来源、例外和未知。发现知识缺口时提出具体问题，由知识责任人处理；本技能不自行重做知识获取，也不要求固定数量的萃取条目。

“必须”区分定义性条件、记录质量、算法前提、业务义务。违反质量或义务的来源应能保留并标注；模型不能只容纳理想状态，从而丢掉需调查的事实。

## 从审阅返回工程

用最小对照记录检查重要取舍，再覆盖适用的缺失、冲突、重复、身份、时间、尺度及不支持分支。无需机械为每个概念建立同样数量的文件。

| 发现 | 返回修改 |
| --- | --- |
| 同一事实增加证据后业务量翻倍 | 对象粒度、事实采用及去重口径 |
| 业务陈述无法用模型准确表达 | 定义、关系或知识缺口 |
| 证据不足仍输出正式认定 | 结果语义、适用前提与核实责任 |
| 平台不能表达业务承诺 | 适配和外部责任；保留原要求及缺口 |
| 概念修改后结构化内容与审查稿含义不同 | 模型、审查稿、案例解释和确认范围同步更新 |

作者先解决能解决的问题。需业务裁定的分歧进入确认清单；有记录、责任人和适用版本的答复才是确认。模型正确性由领域审阅、形式检查和使用验证共同支持，不能由字段齐全判定。
