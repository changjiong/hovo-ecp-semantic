# domain-knowledge 0.8.0 本地候选修订

任务依据：2026-09-14 用户要求形成任务清单并执行跟踪。合同版本 4.0.0，不提供旧合同兼容路径。

## 变更

- 先从原文拆解业务含义，再发现、归并问题；保留候选去向和参与者/流程补查。
- 原文摘录与业务含义陈述分开，材料映射与语义审查分开；样章的已审状态不扩为全量。
- `review.md` 面向业务阅读，`coverage.md` 承接全量台账；共享结构化内容与版本摘要。
- 具体案例解释判断，取消固定四类凑数；业务评审延续既有真实答复，只追问未决含义。
- 新增 `render_documents.py` 生成双文档；变更后结构检查状态重置为未执行。

## 本轮落地

A01 保留七份权威材料的现有解析结果，仅将国企识别、形成日期、差异处理作为深度样章。其余业务主题及概念实例的缺口继续显式登记。没有进行全量业务语义验收。

任务及交付证据见 `A01受益所有人/04领域知识输出/tasks.md`。独立检查发现的文档状态、抽取状态展示、确认记录绑定等缺口已修正。Schema 3 项、A01 输入/输出合同和 skill-creator 入口检查通过；实际业务读者验证和责任人批准尚未完成。当前为本地候选，未提交、发布或验证清洁安装。

技能目录被当前仓库忽略；本次通过 `references/sources.json` 固定资源版本、字节数与 SHA-256。旧 reports 仅代表其记录的旧版本。

实际校验边界：独立审阅者执行首轮静态审查及 Schema 检查；主代理执行修正后的实际合同脚本。正式签认/过期交互未作完整运行验证，不宣称该范围已验收。大台账锚点检查由重复全文扫描改为一次扫描；当前实际输出检查耗时见 A01 validation.json。
