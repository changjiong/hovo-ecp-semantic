# 《领域业务知识说明书：设备维护教学样例》

**版本：教学草案 1.1；编制日期：2026年4月2日；状态：未确认。**

本文只根据文末两份专为教学编制的合成材料整理，不对应客户制度、真实设备或实际处理记录。文中明确区分“材料记载”“分析推断”“建议口径”和“待确认”；建议不是规则，作者也没有取得或代填任何业务人员答复。

<a id="section-scope"></a>
## 一、目标、范围与业务全貌

这是一份供业务负责人、领域专家和需求访谈人员阅读的教学说明书。它讨论的不是某组织当前如何运作，而是展示：面对“设备是否应进入日常维护安排”和“停用且日期已超期的设备如何处理”两个问题，怎样将材料、事实、判断和待确认事项讲清楚。计划人员可把结果作为访谈或复核候选，不能把它当成维修指令、安全放行、停用解除或正式业务决定。

本样例纳入设备识别、上次保养日期、保养周期、在用或停用的记录、日常维护安排和恢复使用申请；业务时点是假定作出本次判断的当天，材料版本为文末所列教学合成稿。两份材料没有交代真实组织的现行流程、授权主体、停用有效条件、周期算法和完成时限。因此，下文的“教学用处理顺序”只是整理建议，真实流程、制度版本和参与者授权均待取得。

事情可以从一份待审设备清单开始：先知道设备及其可追溯记录，再对照适用材料形成候选结果；日期或状态不足时补证，两个材料交叉而无优先级时提出访谈问题。结果的使用边界见[是否进入日常维护安排](#是否进入日常维护安排)和[停用且日期已超期如何处理](#停用且日期已超期如何处理)。

<a id="section-concepts"></a>
## 二、关键概念与已有认识

**设备。** 教学暂定为本次维护判断所指向的一个可识别资产。正例是有资产编号的空压机；反例是未指向具体资产的采购申请单。仅名称相同或移动地点都不足以确认是同一设备。两份材料只使用“设备”一词，未给出身份规则，因此该定义是**教学暂定**，真实资产识别规则**待确认**。

**上次保养日期。** 教学暂定为可追溯记录中所载的最近一次已完成保养日期。正例是写明“2026年3月1日完成例行保养”的记录；反例是仅写“拟于2026年3月1日保养”的计划。材料A第2段要求记录保留保养日期和执行人员，但没有规定何种记录证明完成，故“最近一次”和证明力均属**分析推断，待确认**。[材料A第2段](#source-a-2)

**保养周期。** 是用于比较是否超过周期的间隔要求。材料A第1段**材料记载**设备超过保养周期应安排维护。正例是记录明确为30日的周期；反例是一次临时巡检，不能当然改变周期。自然日、工作日和运行时长等计算口径在材料中均无依据，属于**待确认**。[材料A第1段](#source-a-1)

**到期日和超期。** 教学暂定为按已确认起算口径从上次保养日期推得的日期，以及判断日严格晚于该日期的情形。正例是在统一算法下判断日晚于到期日；反例是判断日恰好等于到期日。材料A没有定义起算和当天处理，因此该界限是**分析推断，待确认**，不能以名称相近替代规则。[材料A第3段](#source-a-3)

**在用设备。** 本样例的候选含义是在本次判断日实际处于使用状态、承担预定用途的设备。正例是当天正在按正常安排供气的空压机；反例是已经停止使用且等待处置的设备。“台账记录为在用”只是来源对状态的记载，不能直接等同于现实状态。材料A、B均未定义在用范围和证明方式，候选含义待确认；仅无停用记录或状态为空时，不能推定在用。

**停用设备。** 本样例的候选含义是在适用业务安排下已经停止投入正常使用的设备。正例是明确撤出正常运行安排、等待后续处置的设备；反例是仍在正常运行安排中、只在班次间短暂停机的设备。台账中的“停用”是状态记载，设备、实际状态与记载本身不是同一事物。材料B第1段未定义停用的生效条件、期限和可采信依据，因此上述边界和某条停用记录的证明力均**待确认**。[材料B第1段](#source-b-1)

**日常维护安排。** 教学暂定为按适用业务流程决定并组织对设备开展维护。正例是已确定需要维护并安排相应执行事项；反例是仅被列为“可能需要维护，等待核实”的候选。计划记录可能记载安排，但记录不是维护完成事实。本样例只能提出维护候选，不能证明安排已经作出。材料A第1段使用“安排维护”，材料B第1段使用“日常维护计划”，两者范围是否一致以及如何形成正式安排均待确认。[材料A第1段](#source-a-1) [材料B第1段](#source-b-1)

**缺证。** 是完成当前判断所需事实或其依据未能取得的状态。正例是已有周期但无上次保养完成日期；反例是有可追溯完成日期却只是尚未复核。材料没有定义该词；把它单列为**教学暂定**，是为了避免把缺失当作“没有保养”或“刚保养”。

<a id="section-judgements"></a>
## 三、业务问题与判断依据

### <a id="是否进入日常维护安排"></a>是否进入日常维护安排

这个问题的使用者是假定的计划人员，结果只用于形成候选清单。需要知道设备能否识别、是否有正向在用依据、上次保养完成日期、适用周期和本次判断日；这些是从“超过保养周期”拆出的**分析推断**，不是材料A逐字要求。[材料A第1段](#source-a-1)

教学用判断顺序如下：先核对上述事实是否都有可追溯依据；缺任一事实即输出“不能判断，需补证”。有正向在用依据时，才按**仅供案例的合成算法**比较日期：使用自然日，开始日不计，到期日为上次保养日期后的第30个自然日；判断日严格晚于到期日才称超期。该算法只服务案例计算，材料A未授权把它用于真实计划。[材料A第3段](#source-a-3)

在上述算法前提下，在用且超期的设备可输出“应进入维护安排候选”；未超期可输出“不因超期进入候选”；恰好到期则输出“到期口径待确认”。有停用记录的设备不能直接沿用在用分支，因为材料B只给出“不纳入日常维护计划”，没有说明该例外与超期要求的先后关系。[材料B第1段](#source-b-1)

因此，该问题不能判断保养是否完成、设备是否安全、停用是否有效或谁有权批准实际安排。日期、状态或周期缺失时只能请求相应材料；冲突未裁定时只能保留候选或待确认，不能用默认值给出结论。此问题由[在用且明确超期](#case-positive)、[在用但未超期](#case-negative)、[恰好到期](#case-boundary)和[缺少上次保养日期](#case-missing)覆盖；停用且已超期的交叉分支另由下一问题及[停用且确定超期](#case-stopped)覆盖。

### <a id="停用且日期已超期如何处理"></a>停用且日期已超期如何处理

这个问题讨论材料A与材料B同时出现时应交给谁澄清，不产出既定处理规则。需要设备、可追溯的停用记录、上次保养完成日期、周期、判断日，以及停用记录的生效条件；最后一项是理解“停用设备”的必要事实，但材料B没有提供。[材料A第1段](#source-a-1) [材料B第1段](#source-b-1)

先按同一合成日期算法判断日期是否超期，再单独报告停用记录的存在与其有效性未知。若日期可确定超期且存在停用记录，不能自行选择“安排维护”或“不纳入计划”：两条材料没有给出优先级。可输出的是“停用与超期并存，需确认例外规则和停用有效性”。[材料A第1段](#source-a-1) [材料B第3段](#source-b-3)

本问题不能判断停用是否豁免、是否应立即维护、恢复使用是否重置周期或申请是否已获准。材料不足时，建议访谈对象提供停用依据、恢复使用申请和规则适用意见；其真实角色与授权都待核。该问题由[停用且确定超期](#case-stopped)覆盖交叉分支；仍缺有效停用已确认后的处理依据，以及停用但未到期、停用且恰好到期、停用且日期缺失的反例、边界和缺证案例。[在用设备缺日期](#case-missing)不能替代这些停用案例。待[停用口径](#访谈停用豁免)与[维护范围](#访谈维护范围)明确后补充，当前不宣称该问题已完整验收。

### 教学用处理顺序与建议访谈分工

以下不是实际业务流程，也不分配制度裁定权。作为**整理建议**，可由计划记录的持有者说明台账、保养日期和周期材料；材料B第2段点名现场设备负责人提出恢复使用申请，故该称谓可作为停用和恢复使用材料的建议访谈对象。[材料B第2段](#source-b-2) 对周期起算、到期当天和两条材料优先级，建议另向实际领域责任人提问；谁是该责任人、是否有审批权和应走何种既有流程，均待核。

<a id="section-cases"></a>
## 四、案例与结果边界

所有案例均为教学合成事实。除非案例另有说明，日期算法一律是“自然日、开始日不计、上次保养日期后的第30个自然日为到期日、判断日严格晚于到期日才超期”。这是作者为展示边界而设的合成前提，不是材料A或B的规则。

### <a id="case-positive"></a>在用且明确超期（正例）

已知甲设备有资产编号，台账在2026年4月2日正向记录为在用；完成记录写2026年3月1日，周期为30日。步骤是：识别设备和在用依据；按合成算法得出到期日为2026年3月31日；判断日4月2日晚于到期日；最后对照材料A第1段。[材料A第1段](#source-a-1)

预期结果是在合成前提下“应进入维护安排候选”。不得把候选写成已完成保养、已获批准或安全合格，也不得把台账状态当成真实现场状态。真实周期口径和安排授权待确认。

### <a id="case-negative"></a>在用但未超期（反例）

已知乙设备有资产编号，台账在2026年4月2日正向记录为在用；完成记录写2026年3月20日，周期为30日。步骤是：核对同样的事实；按合成算法得出到期日为2026年4月19日；判断日早于到期日；因此材料A的“超过”条件未满足。[材料A第1段](#source-a-1)

预期结果是在合成前提下“不因超期进入维护安排候选”。不得仅因设备在用就称其超期，也不得把该结果扩展为无需巡检、无需维修或可安全运行。真实制度可能另有其他维护要求，本文没有材料。

### <a id="case-boundary"></a>恰好到期（到期边界）

已知丙设备有资产编号，台账在2026年4月2日正向记录为在用；完成记录写2026年3月3日，周期为30日。步骤是：核对事实；按合成算法得出到期日为2026年4月2日；判断日恰与到期日相同；材料A没有规定当天是否已属“超过”。[材料A第3段](#source-a-3)

预期结果是“到期当天口径待确认”。不得直接写为超期或无需安排，更不得改动日期使其落入任一分支。此例直接关联[到期当天是否属于应安排维护的情形](#访谈到期当天)。

### <a id="case-missing"></a>缺少上次保养日期（缺证）

已知丁设备有资产编号，台账在2026年4月2日正向记录为在用，周期写30日；没有可追溯的上次保养完成日期。步骤是：设备和在用依据虽可读取，但日期缺失；不能计算到期日；材料A第2段虽要求保留日期，也没有把缺失解释为已完成或未完成。[材料A第2段](#source-a-2)

预期结果是“不能判断是否超期，需补取完成日期及其依据”。不得把缺失日期当作刚保养、未保养或已超期。本例只覆盖缺证分支，不证明停用且超期的情形。

### <a id="case-stopped"></a>停用且确定超期（交叉分支）

已知戊设备有资产编号；记录在2026年4月2日标作停用，完成记录写2026年3月1日，周期为30日。步骤是：按合成算法先得出到期日2026年3月31日，判断日已晚于该日；再读取材料A要求安排维护与材料B说停用设备不纳入日常维护计划；最后保留未写明的优先级和停用有效性。[材料A第1段](#source-a-1) [材料B第1段](#source-b-1)

预期结果是“日期已按合成算法超期，且存在停用记录；处理规则待确认”。不得输出“无需维护”“必须立即维护”或“停用已有效”。本例关联[停用是否豁免超期维护](#访谈停用豁免)，但仍不能代替真实停用依据和制度答复。

## 五、分歧与需求访谈清单

### <a id="访谈周期起算"></a>保养周期从何时起算

触发材料是[材料A第1段](#source-a-1)的“超过保养周期”。待问含义是从完成日期、计划日期、验收日期还是设备投用日期起算。候选处理为分别采用完成日期、计划日期或运行时长；**暂不推荐**任一选项，因为材料没有起点依据。它影响[在用且明确超期](#case-positive)、[在用但未超期](#case-negative)、[恰好到期](#case-boundary)和[停用且确定超期](#case-stopped)。建议向实际维护制度责任人和记录持有者访谈，真实角色、授权和答复均为“待访谈”。未解决前只能使用合成算法讨论案例，不能形成真实计划规则。

### <a id="访谈到期当天"></a>到期当天是否属于应安排维护的情形

触发材料是[材料A第3段](#source-a-3)明确未规定当天处理。候选处理为当天安排、次日才按超期安排或按另有制度分类处理。**暂不推荐**具体选项；材料没有设备分类和风险依据。它直接影响[恰好到期](#case-boundary)的预期结果。建议向实际领域责任人访谈；真实答复为“待访谈”。未解决前，该案例只能停在待确认，不能写成默认的肯定或否定结论。

### <a id="访谈停用豁免"></a>停用是否豁免超期维护

触发材料是[材料A第1段](#source-a-1)与[材料B第1段](#source-b-1)的交叉。候选处理是停用期间豁免、暂缓且恢复使用前补做，或按停用原因和期限分支。**建议**暂时采用“停用与超期并存时不自动下结论、先核停用依据并访谈”的审阅方式；理由是两条材料均未写优先级。该建议只约束本说明书的表达，不能替代制度。它影响[停用且确定超期](#case-stopped)，并应补充“有效停用已确认”的案例。建议访谈对象是实际制度责任人和停用记录持有者；真实角色、授权和答复均为“待访谈”。

### <a id="访谈完成依据"></a>哪些记录能够证明上次保养完成

触发材料是[材料A第2段](#source-a-2)仅要求保留日期和执行人员。候选处理是以关闭且验收的工单、执行人员签字或两者组合为准。**暂不推荐**，因为材料没有说明验收、签字或工单的证明力。它影响全部需要日期计算的案例，尤其是[缺少上次保养日期](#case-missing)。建议向实际维护记录责任人和制度责任人访谈；真实角色、授权和答复均为“待访谈”。未解决前，日期无法追溯的设备只能列为缺证。

### <a id="访谈维护范围"></a>安排维护与纳入日常维护计划是否是同一件事

触发材料是[材料A第1段](#source-a-1)使用“安排维护”，[材料B第1段](#source-b-1)使用“日常维护计划”。待问两者是否范围相同，还是后者只包含某类例行工作。候选口径为同一范围、日常维护只是维护的一部分，或分别受不同流程约束。**暂不推荐**具体口径；材料没有范围定义。它影响两条规定是否实际冲突、[停用且确定超期](#case-stopped)能否分为不同处理以及候选如何变成正式安排。建议向实际制度责任人和计划执行人员访谈，真实角色、授权和答复均为“待访谈”。未解决前同时保留两种称呼和来源，不将“不纳入日常计划”扩大为“不需要任何维护”。

## 六、合成原始材料与依据索引

### 《设备日常保养安排说明（教学合成稿）》

提供方：本文作者为教学编制；版本：教学合成稿1.0；日期：2026年4月2日；适用限制：不是客户制度，未获业务确认。

<a id="source-a-1"></a>**第1段：**“为保持设备处于可维护状态，设备超过保养周期应安排维护。”支持“超过周期”与“安排维护”的材料记载；不支持周期起算、到期当天、授权主体或最晚完成时间。

<a id="source-a-2"></a>**第2段：**“维护记录应保留设备名称、保养日期和执行人员，供计划复核使用。”支持需保留日期与执行人员的材料记载；不证明记录真实、完整或足以证明保养完成。

<a id="source-a-3"></a>**第3段：**“本说明未规定保养周期的起算日期、到期当天的处理或超过周期后的最晚完成期限。”明确本说明书应保留这些待确认项。
