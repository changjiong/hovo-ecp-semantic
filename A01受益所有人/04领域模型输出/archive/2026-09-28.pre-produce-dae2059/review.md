### 核心领域判断

| 判断 | 采用的业务事实 | 结果或人工边界 |
| --- | --- | --- |

| 核验并计算权益穿透路径 | 自然人评估、权益关系边 | 逐条核实路径节点与边，计算每条有效路径贡献并核定路径全集状态；合计由 M.SumEquityPaths 给出。 |
| 核实自然人身份与权利证据 | 候选评估、候选证据 | 分别核对自然人身份、权利来源、证据可靠性及适用时点；资料字段齐全不等于权利已核实。 |

| 裁定实际控制 | 控制安排 | 依据具体决定权限、实际作用和证据判断自然人是否单独或联合最终支配组织。 |

## 业务对象及其关系

以下逐个解释对象为何存在、如何区分业务实例以及它与其他对象怎样连接。详细字段矩阵和规则原文对应保留在 coverage.md。

### 组织主体

金融机构把组织主体作为客户，或把它作为权益链中的中间节点来识别最终自然人。

受益所有人识别的目标组织或权益链中的中间组织。

**为何单独建模：**目标组织与中间持股组织具有独立身份；权益路径必须明确每段指向的组织。

**如何区分实例：**以登记识别号与登记/设立法域区分同名组织；更名或恢复登记须有连续身份和有效期间证据。

**名称依据：**沿用领域知识中的业务用语。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 登记识别号 | 必须一项 | 官方登记或设立文件中的稳定主体识别号。缺失时不能虚构组织身份。 |
| 登记/设立法域 | 必须一项 | 该组织登记或依法设立的法域，用于解释组织身份及证据适用范围。 |
| 组织身份依据 | 至少 1 项，不限最多数量 | 登记、设立、产权、章程或治理依据。；关联识别证据 |

**例子：**有登记号和法域、且在判断日存续的公司客户。

**不能混同：**名称相同但登记身份不同的组织不能合并为同一主体。

### 自然人

某个自然人依据股权、最终收益/表决权、实际控制，或特定条件下的备位路径，被评估是否为组织客户的受益所有人。

最终受益所有人必须落到的现实自然人；身份同一性与其权利是否达标分别判断。

**为何单独建模：**权利证据可能指向不同候选人；只有身份核实后才能把权利事实绑定到一个现实自然人。

**如何区分实例：**优先按证件类别、号码与签发法域识别；同名、证件更新或多份证据之间的连续性需要独立核实。

**名称依据：**沿用领域知识中的业务用语。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 身份证明类别 | 必须一项 | 官方核验或有效身份证明所载类别。 |
| 身份证明号码 | 必须一项 | 与签发法域共同用于识别个人的号码。 |
| 签发国家或地区 | 必须一项 | 身份证明签发国家或地区。 |
| 出生日期 | 可有一项；缺失时保留未知 | 金融机构一般客户识别所需身份信息。 |
| 证件有效期限 | 可有一项；缺失时保留未知 | 所用身份证明的有效期限；过期不自动抹除历史身份。 |

**例子：**甲以已核验证件身份持有目标公司的间接权益。

**不能混同：**仅以姓名字符串相同就合并的两名自然人。

### 识别证据

识别人员用可定位材料支持或质疑一个特定身份、权利事实及其有效期间。

支持自然人身份、组织身份、权利关系或有效期间的可定位来源记录。

**为何单独建模：**增加第二份材料不会自动增加一个业务主体；证据需与它支持的事实和期间绑定。

**如何区分实例：**以来源标识与材料位置区分；同一材料的不同页、条款或查询快照分别定位，不以系统流水号替代来源事实。

**名称依据：**建模建议用语，需评审其含义和可读性。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 来源记录标识 | 必须一项 | 来源文件、官方查询或客户原始材料的可回溯标识。 |
| 材料位置 | 必须一项 | 页码、条款、登记记录或查询结果位置。 |
| 材料出具日 | 可有一项；缺失时保留未知 | 来源材料被出具的日期，不自动视为权利生效日。 |
| 材料取得日 | 可有一项；缺失时保留未知 | 金融机构取得该材料的日期。 |
| 机构核实日 | 可有一项；缺失时保留未知 | 机构完成该材料核实的日期；不替代权利形成日。 |
| 对外披露日 | 可有一项；缺失时保留未知 | 来源事实对外披露的日期；不替代法律关系生效日。 |

**例子：**章程特定条款支持某人有权提名多数董事。

**不能混同：**第三方平台给出的比例标签直接作为已核实的最终权益。

### 权益持有关系

在某一时点，某个组织或自然人通过一条有效权益边持有另一个组织的一定股权或合伙权益。

某组织在特定期间向另一组织或自然人持有股权、股份或合伙权益的单条关系边。

**为何单独建模：**直接与多层间接比例须按边计算并区分多条路径；把关系作为事实边可保留路径、期间和证据。

**如何区分实例：**同一目标、持有人、权益类别与生效区间构成关系身份；若身份字段或期间不明，不生成伪造的完整关系。

**名称依据：**建模建议用语，需评审其含义和可读性。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 被投资/持有权益的组织 | 必须一项 | 路径中接受该段权益的组织。；关联组织主体 |
| 持有人类别 | 必须一项 | 每条关系边只有一个持有人类别。；可选值：ORGANIZATION、NATURAL_PERSON |
| 持有人组织 | 可有一项；缺失时保留未知 | 当 holder_kind 为 ORGANIZATION 时填写。；关联组织主体 |
| 持有人自然人 | 可有一项；缺失时保留未知 | 当 holder_kind 为 NATURAL_PERSON 时填写。；关联自然人 |
| 权益类别 | 必须一项 | 能够区分同一双方之间不同权益安排的业务类别。 |
| 权益关系依据标识 | 必须一项 | 来源文件/登记权利关系中的稳定引用；无依据不构造事实边。 |
| 本段关系精确生效日 | 可有一项；缺失时保留未知 | 仅在可证实精确法律生效日时填写；登记或查询日期不能代替。 |
| 本段关系终止日 | 可有一项；缺失时保留未知 | 有证据时记录终止日；未知或未终止与OPEN状态分别处理。 |
| 持有关系证据 | 至少 1 项，不限最多数量 | 支持持有人、比例和期间的材料。；关联识别证据 |

**例子：**甲持有B公司30%，B公司持有客户A 80%，两条边分别留存。

**不能混同：**把B公司控制客户A解释成甲持有A公司100%权益。

### 权益穿透路径

识别人员逐条记录自然人到目标组织的权益路径及逐边相乘的单路径贡献。

从一个自然人经由有序权益关系边抵达目标组织的单条无环路径及其权益贡献。

**为何单独建模：**显式保留有序边和路径贡献，避免把中间组织控制当作100%权益或丢失多路径依据。

**如何区分实例：**以目标组织、自然人、时点和有序边序列区分；关系变化产生新的时点路径。

**名称依据：**建模建议用语，需评审其含义和可读性。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 目标组织 | 必须一项 | 路径终点组织。；关联组织主体 |
| 最终自然人 | 必须一项 | 路径起点自然人。；关联自然人 |
| 路径判断时点 | 必须一项 | 所有路径边按同一时点筛选。 |
| 路径标识 | 必须一项 | 区分同一人到同一组织的不同关系路径。 |
| 有序路径步骤 | 至少 1 项，不限最多数量 | 按 step_order 排序，每步引用一条权益边。；关联权益路径步骤 |
| 路径核验证据 | 至少 0 项，不限最多数量 | 支持路径中各边及期间的来源材料。；关联识别证据 |

**例子：**甲通过B再到目标组织的间接路径按两段比例相乘。

**不能混同：**把B控制目标组织解释为甲持有目标组织100%权益。

### 权益路径步骤

一条权益边在某条具体路径中占据确定顺序位置。

某权益关系边在一条穿透路径中的有序位置。

**为何单独建模：**同一关系边可被多条路径引用；序号支持逐边计算回放。

**如何区分实例：**以路径与路径内序号区分。

**名称依据：**建模建议用语，需评审其含义和可读性。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 所属路径 | 必须一项 | 对应的单条权益路径。；关联权益穿透路径 |
| 权益关系边 | 必须一项 | 该步骤采用的已核权益边。；关联权益持有关系 |
| 路径顺序 | 必须一项 | 从自然人一侧到目标组织一侧的正整数顺序。 |

**例子：**路径P的第2步引用B持有目标组织的权益边。

**不能混同：**把多条不同路径合并成无序边集合。

### 受益所有权关系角色

**如何区分实例：**目标组织、自然人、识别依据与生效期间共同识别一段关系；退出后重新达标形成新的关系区间。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 受益所有人自然人 | 必须一项 | 角色承担者必须是自然人。；关联自然人 |
| 目标组织 | 必须一项 | 受益所有权所指向的组织。；关联组织主体 |

**如何区分实例：**以目标组织与判断时点识别一份结论快照；新证据可修订新版本，不覆盖原判断依据。

| --- | --- | --- |

| 识别责任角色 | 必须一项 | 金融机构有权尽调人员；本模型不规定准入/授信/报告审批岗位。；关联金融机构识别责任角色 |

## 逐项业务问题

### 自然人直接持有多少股权、股份或合伙权益才达到标准，恰为25%是否包括？

按经核实的直接权益比例判断；25%含本数。低于该标准仍须继续检查收益/表决和实际控制。

**建模情况：**已建模。由稳定事实、权利关系和领域判断承接，不依赖工作流。

**汇总同一自然人有效权益路径：**完整性仍须由责任人员据全图证据核定；仅对已核实、互异且有效的路径贡献求和。

采用事实：互异权益路径、整体路径状态。

结果记录在：自然人识别评估的最终权益比例；缺失输入按未知值传播。

**权益比例达到25%：**25含本数；仅对同一判断时点、证据支持的最终权益比例求值。路径不完整、循环或冲突时比例保持未知，不按0处理。

采用事实：最终权益比例（百分比）、整体路径状态。

结果记录在：自然人识别评估的符合权益标准；缺失输入按未知值传播。

**核验并计算权益穿透路径**

责任：金融机构识别责任角色。

- 从自然人一侧到目标组织一侧为每条路径建立有序边步骤。
- 逐边相乘并记下每条路径贡献；不得把中间组织控制比例当作100%权益。
- 同一自然人的互异有效路径分别计算后合计，不重复计入同一关系路径。
- 缺边、循环、冲突或日期不明影响总量时整体保留UNKNOWN，不把未查明比例按零处理。

所需证据：每段持有人身份及比例的有效依据；同一判断时点的完整上层结构；循环、交叉、重复路径和关系期间核对记录。

复核要求：这是有序图事实上的人工/确定性计算边界；本领域模型未声称提供任意深度图遍历运行时。

### 间接持股经过哪些有效上层主体和路径，如何逐路径计算同一自然人最终拥有比例并汇总？

逐层核实有效权益边，对每条无环路径逐段相乘，再合计同一自然人的互异有效路径；循环、交叉或缺边时受影响合计保持UNKNOWN。

**建模情况：**已建模。由稳定事实、权利关系和领域判断承接，不依赖工作流。

沿用前述判断：**汇总同一自然人有效权益路径**。

沿用前述判断：**权益比例达到25%**。

沿用前述人工准则：**核验并计算权益穿透路径**。

### 登记持股与代持、受益权转移不一致时，登记股东是否仍为最终拥有者、实际权益归属谁？

登记名义人不自动等于最终权利人；分别核对最终权益、收益、表决及实际控制的协议、履行和期间。

**建模情况：**部分建模，有待解决事项。核心识别结构和判断已承接；关联的上游OPEN事项继续保持未决。

**核实自然人身份与权利证据**

责任：金融机构识别责任角色。

- 身份真实性与自然人身份同一性可被可靠来源支持。
- 材料支持具体权益、收益/表决或控制关系及对应期间，而非仅有姓名或比例标签。
- 客户材料与独立信息相符；存在冲突时先记录受影响事实并补证。

所需证据：自然人官方身份核验结果或有效身份证明与补充材料；组织登记/章程/协议/权利记录及其生效期间；独立来源交叉核实及冲突处理记录。

复核要求：核验结论由金融机构责任人员记录；具体岗位授权依机构制度，本模型不作推定。缺身份或权利证据时阻断受影响结论而非把未知记为否。

**待解决：**具体客户的代持效力、最终权利归属或实际控制证据可能冲突；未取得并核对案件材料前，不确认受影响自然人及关系形成时点。

### 自然人未满足持有权益标准，却最终享有多少收益权，是否达到25%，收益权从何而来？

仅在该自然人未达到标准一时，按最终收益权是否达到25%判断标准二；单笔分配额不足以证明最终比例。

**建模情况：**已建模。由稳定事实、权利关系和领域判断承接，不依赖工作流。

**收益/表决权标准达到25%：**权益标准一为真时标准二归类为假；否则收益权或表决权任一达到25%即为真。标准一未知或两种权利均无法确定时按三值逻辑传播未知。

采用事实：已符合权益标准、最终收益权比例、最终表决权比例。
