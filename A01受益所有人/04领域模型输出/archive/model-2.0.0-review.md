## 业务对象及其关系

以下逐个解释对象为何存在、如何区分业务实例以及它与其他对象怎样连接。详细字段矩阵和规则原文对应保留在 coverage.md。

### 组织主体

金融机构把组织主体作为客户，或把它作为权益链中的中间节点来识别最终自然人。

受益所有人识别的目标客户或持有权益链中的中间组织。分支机构不与所属组织合并。

**为何单独建模：**目标客户、中间持股主体和分支所属组织承担不同上下文；组织形式和时点会改变适用识别路由。

**如何区分实例：**以登记识别号与登记/设立法域区分同名组织；更名或恢复登记须有连续身份和有效期间证据。

**名称依据：**沿用领域知识中的业务用语。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 登记识别号 | 必须一项 | 官方登记或设立文件中的稳定主体识别号。缺失时不能虚构组织身份。 |
| 登记/设立法域 | 必须一项 | 该组织登记或依法设立的法域，用于解释组织身份及证据适用范围。 |
| 组织身份依据 | 至少 1 项，不限最多数量 | 登记、设立、产权、章程或治理依据。；关联识别证据 |

**例子：**有登记号和法域、且在判断日存续的公司客户。

**不能混同：**国资交易系统标注的‘实际控制企业’不是自然人受益所有人。

### 自然人

某个自然人依据股权、最终收益/表决权、实际控制，或特定条件下的备位路径，被评估是否为组织客户的受益所有人。

最终受益所有人必须落到的现实自然人；身份同一性与其权利是否达标分别判断。

**为何单独建模：**权利证据可能指向不同候选人；只有身份核实后才能把权利事实绑定到一个现实自然人。

**如何区分实例：**优先按证件类别、号码与签发法域识别；同名、证件更新或多份证据之间的连续性需要独立核实。

**名称依据：**沿用领域知识中的业务用语。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 身份证明类别 | 必须一项 | 官方核验或有效身份证明所载类别。 |
| 身份证明号码 | 必须一项 | 与签发法域共同用于识别个人的号码。 |
| 签发国家或地区 | 必须一项 | 身份证明签发国家或地区。 |
| 出生日期 | 可有一项；缺失时保留未知 | 金融机构一般客户识别所需身份信息。 |
| 证件有效期限 | 可有一项；缺失时保留未知 | 所用身份证明的有效期限；过期不自动抹除历史身份。 |

**例子：**甲以已核验证件身份持有目标公司的间接权益。

**不能混同：**仅以姓名字符串相同就合并的两名自然人。

### 识别证据

尽调人员用某份可定位材料支持或质疑一个特定身份、权利、关系期间或风险事实。

支持组织身份、自然人身份、权益/控制关系、有效期间或风险判断的来源记录。

**为何单独建模：**增加第二份材料不会自动增加一个业务主体；证据需与它支持的事实和期间绑定。

**如何区分实例：**以来源标识与材料位置区分；同一材料的不同页、条款或查询快照分别定位，不以系统流水号替代来源事实。

**名称依据：**建模建议用语，需评审其含义和可读性。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 来源记录标识 | 必须一项 | 来源文件、官方查询或客户原始材料的可回溯标识。 |
| 材料位置 | 必须一项 | 页码、条款、登记记录或查询结果位置。 |
| 材料出具日 | 可有一项；缺失时保留未知 | 来源材料被出具的日期，不自动视为权利生效日。 |
| 材料取得日 | 可有一项；缺失时保留未知 | 金融机构取得该材料的日期。 |
| 机构核实日 | 可有一项；缺失时保留未知 | 机构完成该材料核实的日期；不替代权利形成日。 |
| 对外披露日 | 可有一项；缺失时保留未知 | 来源事实对外披露的日期；不替代法律关系生效日。 |

**例子：**章程特定条款支持某人有权提名多数董事。

**不能混同：**第三方平台给出的比例标签直接作为已核实的最终权益。

### 权益持有关系

在某一时点，某个组织或自然人通过一条有效权益边持有另一个组织的一定股权或合伙权益。

某组织在特定期间向另一组织或自然人持有股权、股份或合伙权益的单条关系边。

**为何单独建模：**直接与多层间接比例须按边计算并区分多条路径；把关系作为事实边可保留路径、期间和证据。

**如何区分实例：**同一目标、持有人、权益类别与生效区间构成关系身份；若身份字段或期间不明，不生成伪造的完整关系。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 受益所有人自然人 | 必须一项 | 角色承担者必须是自然人。；关联自然人 |
| 目标组织 | 必须一项 | 受益所有权所指向的组织。；关联组织主体 |
| 识别依据 | 必须一项 | 同一自然人可以有多个有证据支持的识别依据；备位仅在三项标准均确定不成立时使用。；可选值：EQUITY、ECONOMIC_BENEFIT、VOTING、ACTUAL_CONTROL、FALLBACK_MANAGER |

**例子：**甲因最终权益达到25%在特定期间承担权益标准的受益所有人角色。

**不能混同：**把名义股东身份本身当作受益所有人关系。

### 受益所有人识别结论

金融机构按明确客户范围和时点，交付已支持的自然人关系，并将未决候选、路径或证据缺口显式保留。

金融机构针对一个组织客户和判断时点形成的自然人识别结果、路由、范围完整性和未决事项。

**为何单独建模：**受益所有人姓名、路径、时间、证据、判断状态和业务审批是不同事实；将其合并成单一标签会隐去未知与冲突。

**如何区分实例：**以目标组织与判断时点识别一份结论快照；新证据可修订新版本，不覆盖原判断依据。

**名称依据：**建模建议用语，需评审其含义和可读性。

| 记录什么 | 数量与缺失要求 | 业务含义 |
| --- | --- | --- |
| 识别对象 | 必须一项 | 目标客户或适用分支。；关联组织主体 |
| 判断时点 | 必须一项 | 本结论覆盖的客户关系时点。 |
| 识别路由判断 | 必须一项 | 一般、简化、免识别或阻断状态及依据。；关联识别路由评估 |
| 已支持的受益所有权关系 | 至少 0 项，不限最多数量 | 逐人列明权利标准与有效区间。；关联受益所有权关系角色 |
| 候选评估 | 至少 0 项，不限最多数量 | 包含已入选和未能排除的候选。；关联自然人识别评估 |

**例子：**结论列出甲的控制关系及证据，同时保留另一候选人的路径未知事项。

**不能混同：**仅保存一份无时点、无依据、未决项被清空的自然人名单。

## 业务处理顺序

### 金融机构客户受益所有人识别

**启动条件：**金融机构需要对法人、非法人组织客户或适用分支机构识别自然人受益所有人时。

1. **确认客户与判断时点**：确认金融机构客户身份、组织类别和同一判断时点；不办理或评价备案。

2. **核实分支所属关系**：仅在分支为目标或权益路径节点时执行；关系不明则阻断承继。

   须先完成：确认客户与判断时点。

   登记缺口，继续不依赖该资料的工作。

3. **判定一般、简化或免识别路线**：一般识别为基线；只有组织类别、人选及风险闸门均满足相应规定才采用简化或免识别。

   须先完成：确认客户与判断时点。

4. **建立权益、收益、表决与控制事实**：把名义持有与最终权利、收益权、表决权、实际控制分开，并逐条绑定材料和期间。

   须先完成：判定一般、简化或免识别路线。

   登记缺口，继续不依赖该资料的工作。

5. **核验自然人并逐项评估三类标准**：先逐条有序核算权益路径，再评估三项标准；实际控制与证据真实性由责任人员裁定，未核路径不得按零。

   须先完成：建立权益、收益、表决与控制事实。

   登记缺口，继续不依赖该资料的工作。

6. **仅在组织级无人符合时评估备位**：只有候选全集和全部相关路径核查完整且无人符合一般标准时才启用备位；单个候选不达标不足以触发。

   须先完成：核验自然人并逐项评估三类标准。

7. **选择相称加强核实措施**：针对具体风险事实补证并评价效果；不把风险措施变成通用识别阈值或拒办决定。

   须先完成：核验自然人并逐项评估三类标准。

   登记缺口，继续不依赖该资料的工作。

8. **形成有依据的识别结论**：按自然人、权利标准、有效期间、证据和未决事项记录可支持部分；不输出备案或差异报告。

   须先完成：仅在组织级无人符合时评估备位、选择相称加强核实措施。

   登记缺口，继续不依赖该资料的工作。

## 逐项业务问题

### 备案主体识别与金融机构客户识别是否面对同一对象、作同一个判断、由谁承担各自核实责任？

本模型只表达金融机构对客户的独立识别；不包含企业备案办理，也不以备案记录替代机构核实。

**建模情况：**已建模。该问题在本模型显式范围内由模型元素和识别流程覆盖。

**判定客户识别路由**

责任：金融机构识别责任角色。

- 免识别仅在组织属于法定类别且证据匹配时成立。
- 简化识别须同时满足各类别自身人选条件与适用风险闸门。
- 不满足类别、候选人或风险条件时回一般识别；资格未知时不能默认免识别/简化。
- 国企简化与一般豁免单独核实，不借备案办理或信托/资管产品类别推路线。

所需证据：组织形式与依法设立类别的官方材料；适用简化/豁免路线的人选/负责人材料；与路线相称的客户风险核查事实。

复核要求：本模型只记录金融机构客户识别路径，不形成备案办理、客户准入/授信或对外报告审批结论。

### 自然人直接持有多少股权、股份或合伙权益才达到标准，恰为25%是否包括？

按经核实的直接权益比例判断；25%含本数。低于该标准仍须继续检查收益/表决和实际控制。

**建模情况：**已建模。该问题在本模型显式范围内由模型元素和识别流程覆盖。

**汇总同一自然人有效权益路径：**完整性仍须由责任人员据全图证据核定；仅对已核实、互异且有效的路径贡献求和。

采用事实：互异权益路径、整体路径状态。

结果记录在：自然人识别评估的最终权益比例；缺失输入按未知值传播。

**权益比例达到25%：**25含本数；仅对同一判断时点、证据支持的最终权益比例求值。路径不完整、循环或冲突时比例保持未知，不按0处理。

采用事实：最终权益比例（百分比）、整体路径状态。

结果记录在：自然人识别评估的符合权益标准；缺失输入按未知值传播。

**核验并计算权益穿透路径**

责任：金融机构识别责任角色。

- 从自然人一侧到目标组织一侧为每条路径建立有序边步骤。
- 逐边相乘并记下每条路径贡献；不得把中间组织控制比例当作100%权益。
- 同一自然人的互异有效路径分别计算后合计，不重复计入同一关系路径。
- 缺边、循环、冲突或日期不明影响总量时整体保留UNKNOWN，不把未查明比例按零处理。

所需证据：每段持有人身份及比例的有效依据；同一判断时点的完整上层结构；循环、交叉、重复路径和关系期间核对记录。

复核要求：这是有序图事实上的人工/确定性计算边界；本领域模型未声称提供任意深度图遍历运行时。
