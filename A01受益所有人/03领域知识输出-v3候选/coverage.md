# 2. 这次为什么从22条扩展到69条

上一版22条规则解决了“知识主体是谁”的结构问题，但把多个会独立改变业务结论的判断压在同一条规则中。

3.1.0按以下拆分原则扩展：

> **如果改变一个条件会使业务结论、证据要求、识别路径或后续处置发生不同，这个判断通常应成为独立Rule（业务规则）。**

因此重点拆细了：

- 直接/间接/多路径所有权；
- 标准一与标准二/三优先关系；
- 收益权与表决权；
- 实际控制的不同支配事实；
- 管理人员兜底前提；
- 境内/外国分支；
- 信托/资管不同路径；
- 国企性质、国有参股和简化风险门控；
- 识别与核实；
- 形成时间、历史变化；
- 加强识别；
- 分支机构、信托、资产管理产品等作为一般识别下的主体类型分支，不作为第五种识别制度；
- 重大/非重大差异和处置。

问题框架同步由14个一级问题扩展到30个可独立检查的业务问题，但Question仍不是知识主体。

# 7. 明确排除的系统实现知识

S06以及实践材料中大量以下内容不进入核心领域知识：

- 实时/批量接口顺序；
- 流水号有效期；
- 报文字段与错误码；
- 附件上传、参数通知；
- 产品页面操作；
- 厂商推荐排序和营销能力。

它们可以进入作业流程、系统接口、`ecp-data-mapping（ECP数据映射）`或应用实现，但不能反向定义“谁是受益所有人”。
