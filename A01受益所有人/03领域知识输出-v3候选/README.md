# A01 受益所有人领域知识 v3 候选

本目录是按 `domain-knowledge（领域知识形成）` 1.1.0 方法重新整理的业务领域知识候选稿。

## 为什么单独建候选目录

当前主线 `03领域知识输出` 已有 2.5.0 的完整结构化成果，但其业务正文仍明显受“问题覆盖、来源单元、接口操作”驱动。PR #7 已重新定义技能边界：

- Term（业务概念）与 Rule（业务规则）是知识主体；
- Question（业务问题）用于发现和覆盖检查；
- Case（案例）用于校准和证伪；
- MinerU（文档解析工具）继续作为文档输入适配层；
- Document Coverage（文档覆盖）不能替代 Knowledge Coverage（知识覆盖）。

因此本目录不直接覆盖旧版正式成果，而先提供一份可由 UBO（最终受益所有人）业务专家独立审阅的候选基线。3.1.0-draft 已从上一版22条高层规则继续拆细到69条独立业务判断，避免“骨架正确但细节过薄”。

## 文件

- [review.md](review.md)：业务人员主读文件，69条核心规则、30个业务问题、核心概念、来源案例和8个 OPEN（未决）事项；
- [coverage.md](coverage.md)：来源层级、规则—来源矩阵、案例覆盖、排除范围和本轮未执行验证。

## 本轮范围

核心纳入：

- 四种识别制度：一般识别、简化识别、免于识别、加强识别；
- 一般识别下按主体类型展开的公司/合伙企业/分支机构/信托/资管产品等分支；
- 标准一、标准二、标准三；
- 日常经营管理人员兜底；
- 分支机构；
- 国有企业性质与简化识别；
- 免于识别与社会组织简化；
- 信托、资产管理产品；
- 识别与核实证据链；
- 形成/终止日期；
- 加强识别和持续更新；
- 备案免报边界；
- BOMIS（受益所有人信息查询管理系统）差异的业务判断与闭环。

有意不把 BOMIS 接口流水、报文字段、错误码、附件上传和参数通知等系统实现知识混进核心业务领域知识。同时明确：分支机构、信托、资产管理产品等都是一般识别下的主体分支；识别制度统一只有一般识别、简化识别、免于识别、加强识别四类。

这份候选稿依据：

1. 仓库现有 `01业务输入`；
2. 既有 `03领域知识输出` 中已经从上述原始材料建立的来源定位和规则依据；
3. 当前 `domain-knowledge` 1.1.0 的新方法重新归纳。

正式替换主线成果前，应在项目运行环境重新执行：

```text
01业务输入
  → document-intake / MinerU
  → Structured Document IR（结构化文档中间表示）
  → domain-knowledge 1.1.0
  → output.json + review.md + coverage.md
  → 业务专家确认
```

## 评审重点

请不要先看“规则数量是否够多”，而是判断：

1. 这 69 条规则是否已经达到 UBO 专家实际判断所需的业务颗粒度；
2. 是否还有系统接口、产品实现或同业观点被误写成领域规则；
3. 哪些 OPEN 应继续保持未决，哪些已经可以由业务专家补成机构正式口径；
4. 哪些内容应继续保留为机构政策，而不写成公共制度知识。
