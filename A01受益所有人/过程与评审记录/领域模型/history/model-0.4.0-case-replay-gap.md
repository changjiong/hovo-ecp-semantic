# 案例动态回放缺口

当前 86 个案例保留了制度/知识层的文字输入、应有结果和禁止结果，适合业务人员逐案阅读；它们没有把自然语言事实转换成 DSL2 的类型化输入记录。因此目前可以验证：案例是否有模型去向、步骤是否有解释、结果和禁止结果是否区分；不能在不补充事实结构的情况下声称每个案例已被 DSL 求值器执行。

动态回放的下一份输入应逐案补充：

- 对应规则或状态机的明确入口；
- 每个入口字段的类型化值、`UNKNOWN` 或人工证据引用；
- 需要的主体、自然人、权益和时间记录及业务身份键；
- 预期的机器结果或明确的人工审查结果；
- 输入快照、模型摘要和执行时间。

没有这些字段时，脚本不得从 `input_facts` 文本猜测数值、日期或证据状态。当前 86 案例继续标记 `NOT_EXECUTED`，由 `case-review.json` 记录静态审查结果。
