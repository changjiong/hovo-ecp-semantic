# A01 领域 DSL 聚焦草案

这是 domain-model 0.6.0 的两个业务问题示例，绑定当前04知识2.1.0；不是原05模型的替换，也不是41题全量形式化。

- `model.yaml`：模型定义；涉及形成日期和差异闭环，问题状态保持 PARTIAL。
- `input.json`：固定问题范围和知识字节，knowledge_basis=DRAFT。
- `facts/`：合成输入，展示当前区间日期和闭环守卫；不代表真实客户证据。
- `delivery/`：从 DSL 生成的业务说明、覆盖表和交接清单（实际生成后出现）。
- `validation.json`：实际交接校验结果（实际运行后出现）。

当有真实中断后再次达标，当前日期应为新连续区间起点；跨类型切换但已证明连续，保留原总体起点。完整性或连续性不明返回 UNKNOWN。差异只有实际更正并复核一致才能从 PENDING 转 RESOLVED，缺证时 BLOCKED。

本例的计算部分可以运行；完整业务案例包含回访展示、证据核验和历史留存，尚未全部形式化，所以5例仍写 BLOCKED。覆盖状态与脚本求值结果各自说明不同范围。
