# ECP Semantic Authoring Kit 1.7

Start with `standards/ecp-semantic-profile-1.0.md` for the formal support boundary. Use `guides/` for asset authoring and `contracts/` for machine-readable validation. Full imports follow `standards/ecp-full-replacement-import-protocol-1.0.md`.

For object-local investigation, read `guides/ecp-scope-json-format.md` and use `contracts/scope-definition-v1.schema.json`. A workspace package that carries Scope must use `contracts/semantic-workspace-package-manifest-v2.schema.json`. Kit 1.7 clarifies Scope Definition v1 Root Bindings: each binding is a governed bidirectional equality edge and is applied to every selected Root Scan row, including rows selected later by Join or Overlay closure; it is not a one-time lookup for the requested seed. It retains the Kit 1.6 finite CONTAINS and STARTS_WITH Compare operators for Feature and Evaluation plans: both operands are statically typed strings, normalized to Unicode NFC, and compared exactly with case sensitivity, no trim, locale folding, wildcard, regular expression, or implicit coercion. It retains the complete Kit 1.5 WeightedTransitiveClosure contract: new definitions explicitly set cross-root path-record and traversal-state budgets, and a global budget breach fails closed without committing partial paths. It retains the finite DateFromDateTime expression used after reading an xsd:dateTime property; it extracts the calendar date expressed by the source lexical value without joining or rewriting source tables. It retains publication-time Mapping-SHACL compatibility: nullPolicy/cardinality/datatype must not contradict the six staged SHACL assets. It retains direct current-source execution: ECP validates the published Mapping against a consistent source snapshot, while upstream batch-completion checks remain outside the engine. These additions do not change ECP Semantic Profile 1.0. They do not require Scope declarations in Ontology Turtle.
