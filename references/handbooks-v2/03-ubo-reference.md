# UBO与实际控制人本体语义工程样板
## V2.0｜审阅修订版

**UBO：**本册使用该缩写指“最终受益所有人”；涉及中国具体制度时，以制度原文“受益所有人”的定义与适用范围为准。

**文档职责：**用一个实际交付、可重复运行的最小参考工程，演示前两册如何落地。

**基线与日期：**以本次对话生成的第三册 V1.0 为基线；2026年9月7日。

**交付状态：**合成数据的本地可执行参考候选。不是完整监管识别系统，不是经银行批准的生产资产，也未通过ECP（企业认知平台）编译。

## 1. 样板范围与成功标准

### 1.1 本次真正交付什么

随本册交付 `参考工程/ubo-reference/`（参考工程目录）。它完成：合成来源模式校验、来源断言映射、按显式采信记录与双时间组装事实视图、直接股东查询、限定普通股无环结构的精确比例传递、候选门槛演示、输入不足处理、可追踪输出和41项本地合同回归。

同时提供本体文件、标准SHACL（形状约束语言）文件、认定记录表达例、数据映射说明、独立预期、执行配置和测试日志。标准约束验证入口已交付，但当前环境未能安装其依赖，故该项明确为未执行。

### 1.2 能力边界

| 内容 | 本次范围 |
|---|---|
| 自然人与组织、权益持有位置、来源断言 | 有机器模型和合成实例 |
| 来源重复、值冲突、追溯更正、未知时间与缺比例 | 有可运行处理和回归 |
| 直接查询、普通股无环比例连乘及不同路径汇总 | 有实现；使用精确分数，不先舍入 |
| 实际控制人及受益所有人记录主体范围 | 有表达例与显式应用合同检查 |
| 控制安排、客户申报、备案查询、机构拟识别 | 有相互区分的表达例，不自动认定法律事实 |
| 协议控制、特殊表决权、信托、代持及全部组织形式 | 不实现；不得套用普通股算法 |
| 真实实体消歧、材料真实性核验、业务审批 | 未执行；合成输入已显式给定身份和采信 |
| 完整OWL（网络本体语言）一致性与类可满足性 | 未执行，不冒充已验证 |
| ECP（企业认知平台）导入、编译和运行 | 未执行；本工程不是其专用工作区导入包 |

成功标准不是自动给出“最终受益所有人是谁”，而是证明一个有限语义切片可以被独立运行、检查和反驳，并明确不知道、不支持或未完成的部分。

### 1.3 法规语义与工程例子的分界

一般实际控制人的主体范围不能限为自然人。人民银行答记者问明确区分：实际控制人可以是法人或自然人，受益所有人应穿透至自然人。因此，本样板将实际控制人记录连接到“主体”，将受益所有人记录的被认定对象限制为“自然人”。[L1]

《金融机构客户受益所有人识别管理办法》第4条要求必要的风险判断和识别核实，不允许仅依赖备案查询或直接以批量自动化辅助手段替代；第23条另要求识别结果与备案信息查询核对。[L2] 本样板据此区分记录来源和效力，不把备案标签当作银行核实结论。

本样板使用0.25作为普通所有权候选门槛演示参数，与该办法第8条的比例条件相联系，但没有实现该条及其他条文的全部条件、其他权利分支、风险措施、豁免或兜底逻辑。候选集合为空不得触发自动兜底；未发现不等于已证实不存在相应情形。[L2]

## 3. 领域对象与建模决定

### 3.1 核心概念

| 概念 | 本样板定义 | 身份或粒度 |
|---|---|---|
| 主体 | 参与所有权或认定关系的人或组织 | 明确的演示主体标识；不按姓名匹配 |
| 权益持有位置 | 持有人对特定组织、特定权利及计量口径的持有位置 | 持有人＋发行组织＋权利类型＋股份类别＋分母口径 |
| 来源断言 | 来源就某权益位置作出的带时间、口径与来源的陈述 | 一项来源陈述及其标识；不等于权益 |
| 任务事实视图 | 指定时点、知识截止与采信记录下可消费的事实集合 | 一次固定上下文及其选入断言 |
| 控制安排 | 可能影响控制的协议或其他安排 | 安排本身；与承载文档、对安排的断言分开 |
| 认定记录 | 某主体在某制度和任务上下文中作出的识别或核实记录 | 一次业务记录，不是自然人的永久布尔属性 |
| 所有权路径 | 计算时引用已采信权益位置形成的派生路径 | 本样板作为输出制品，不当原始持股事实 |

关系对象是本样板的适用选择，不是所有项目唯一合法结构。采用该模式是因为比例、身份、时间和来源必须在同一持有位置上可追踪。[S2]

### 3.2 三项重要建模决定

**决定一：位置身份不包含当前比例。**比例变更可以通过新的带有效期断言表达；持有人、发行组织、权利种类或计量口径改变时，不沿用同一位置身份。本样板不将位置解释为可交易证券批次或完整法律权利簿。

**决定二：比例只在断言和任务视图中出现。**来源的原值与尺度保存于断言；可归一化的陈述具有对应标准数值，但不会自动成为基础事实。采信视图才提供计算用比例。

**决定三：路径和候选是派生制品。**路径引用权益位置及通过视图间接引用来源。候选输出附带方法、阈值、完整性、限制和批准状态，不覆盖原始数据，也不自动认定为正式受益所有人。

### 3.3 正式模型的位置

`model/ontology.ttl`（本体模型）包含主体、权益位置、断言、视图、控制安排和认定记录的最小类型与关系。`model/record-examples.ttl`（记录表达例）分别表示客户申报、备案查询、机构拟识别和法人控制人记录。

本体里持有人值域为主体，不误设为仅自然人。受益所有人自然人限制在特定结果合同及对应约束中表达。数据约束不能从原始来源自动推断真实性。[S3]

## 4. 完整合成实例与来源映射

### 4.1 基础持股结构

| 来源断言 | 权益位置 | 持有人 | 发行组织 | 原比例 |
|---|---|---|---|---|
| a1 | E1 | P1 林甲 | A 甲有限公司 | 60% |
| a2 | E2 | P2 林乙 | A 甲有限公司 | 40% |
| a3 | E3 | A 甲有限公司 | T 目标有限公司 | 70% |
| a4 | E4 | P3 林丙 | T 目标有限公司 | 20% |
| a5 | E5 | P4 林丁 | T 目标有限公司 | 10% |

A与T的普通股所有权各自合计100%。不同于V1.0的局部图，本例完整写出A剩余40%和T剩余10%。所有记录从2026年1月1日起至7月1日前有效，1月10日进入演示系统知识范围。

完整性来自 `fixtures/coverage.json`（合成覆盖声明），仅指普通股所有权维度和给定期间；它由样例作者作为输入给定，不由“合计100%”自动推导，也不包含对代持和控制安排的核实。

### 4.2 已给定而非猜测的源模式

`fixtures/source-records.json`（合成来源记录）是实际随包文件；`spec/source.schema.json`（来源模式）定义其结构；`spec/mapping.json`（映射说明）将真实存在于该合成文件中的字段映射到语义对象。

这不是银行真实数据库映射，也不是ECP（企业认知平台）专用映射格式。真实项目应提供其自己的模式和身份绑定后再替换对应输入适配。

| 源字段 | 语义解释 | 处理要求 |
|---|---|---|
| `id`（源断言标识） | 一条来源陈述的身份 | 重复标识拒绝；不得冒充多份权益 |
| `position`（位置标识） | 已明确绑定的权益位置 | 同一位置的身份维度不能自相矛盾 |
| `holder / issuer`（持有人／发行组织） | 主体引用 | 未知主体保留来源、阻塞该位置 |
| `value / scale`（原值／尺度） | 比例原始表达 | 字符串精确解析；百分比除100；不补零 |
| `right / share_class / denominator`（权利／类别／分母） | 可比及计算口径 | 其他权利不混入普通所有权分支 |
| `valid_from / valid_to / end_kind`（起止／终止类型） | 业务有效区间 | 有限、明确开放和未知分别处理 |
| `known_at`（获知时间） | 系统可使用该来源的最早知识时间 | 不能超出任务知识截止 |
| `source / origin / evidence_locator`（来源／上游／证据定位） | 断言来源链 | 保留同上游转载关系，不制造独立证据数量 |
| `supersedes`（替代引用） | 明确追溯更正 | 只能替代同位置、同身份的先前断言 |

### 4.3 原始记录质量与可计算质量分开

来源模式允许比例或日期为明确缺失值，以便保存材料。进入可计算视图时，缺失比例、未知有效期、未解析身份和冲突位置被排除并报告原因。排除计算不删除来源，也不把“不知道”编码成零。

## 5. 采信记录与事实视图

### 5.1 显式输入的采信，而非算法猜测

`fixtures/selection.json`（合成采信记录）逐条列出采信断言、采信时间和演示依据。记录明确为合成，并非真实业务人员批准。采信时间不能早于本系统获知来源的时间。

本样板不实现来源可信评分、法律真实性核验或自动证据采信。实际项目需要由适用政策或授权核验流程产生该输入。

### 5.2 事实视图组装规则

先校验源模式和引用；再按知识截止过滤尚未知或尚未采信的断言；按业务区间过滤不适用断言；应用明确且有效的同位置更正；按权益位置检查身份与计量；合并值一致的证据；把值冲突、缺值及不支持口径写入问题记录。

对一份权益的两项相同断言，输出一份位置事实及两个来源引用。对同口径同时间55%与60%的冲突，不取平均、不取最大、不多数投票；相关位置暂不进入计算。

其他权利类型不会被丢弃来源，只是不进入本次普通所有权分支。无关公司的缺口不阻塞目标T；目标及到达的上游组织存在缺口时，目标结果的完整性为否。

### 5.3 双时间例子

回归中增加4月1日获知并采信的更正：a1的60%更正为55%，a2的40%更正为45%，均明确追溯至1月1日并引用旧断言。

| 同一业务时点：2月15日 | 可用知识截止 | P1在T中的比例 | P2在T中的比例 |
|---|---|---|---|
| 当时所知 | 2月15日 | 42% | 28% |
| 后来回看 | 5月1日 | 38.5% | 31.5% |

这是明确更正后的两种合法查询，不是“最新来源永远可信”。旧任务仍可使用其原快照复现，新任务记录不同的知识截止与采信输入。

## 6. 计算及结果合同

### 6.1 本次支持的计算前提

仅处理身份已给定、数值口径为普通股占全部已发行权益、比例处于0至1、有效期和知识时点明确的无环所有权结构。每个到达组织需有明确覆盖声明并通过合计检查。

使用十进制字符串转精确分数计算，显示时才输出小数。对不同合法路径求和；对同位置的重复证据不重复求和。循环、深度或路径预算超限、缺覆盖和比例缺口都返回明确问题，不输出“完整候选”。

### 6.2 基础结果

| 人员 | 路径 | 精确比例 | 普通所有权演示门槛结果 |
|---|---|---|---|
| P1 林甲 | E1 → E3 | 0.60 × 0.70 = 0.42 | 命中 |
| P2 林乙 | E2 → E3 | 0.40 × 0.70 = 0.28 | 命中 |
| P3 林丙 | E4 | 0.20 | 未命中本分支 |
| P4 林丁 | E5 | 0.10 | 未命中本分支 |

“未命中本分支”不表示“不是受益所有人”。其他权利、控制及制度分支未在本工程中完成。目标结果的 `full_ubo_assessment`（完整受益所有人评估）固定为否；`automatic_fallback`（自动兜底）固定为否；业务批准为未进行。

### 6.3 输入不完整时的输出

可保留已知路径的局部算术结果，但必须标为局部，不能宣传为最终或完整比例集合。本样板保守地将完整门槛匹配列表置空，另保留问题及局部路径，避免消费者误当正式候选。

发布给其他系统时，应一并传递完整性维度、问题、输入视图、方法和审批状态，不允许只传递人名和比例。

## 7. 控制与认定记录的表达边界

### 7.1 四种对象必须分开

控制安排、记载安排的文档、来源对安排的断言、根据多项事实形成的控制认定，不是同一个东西。本样板只提供一个明确目标、参与人、事项、期间和证据定位的合成董事提名权安排，不从该安排自动认定实际控制。

一般实际控制人记录允许被认定主体为组织或自然人；受益所有人记录要求自然人。这个字段范围检查只说明记录结构是否符合合同，不证明具体认定成立。[L1]

### 7.2 申报、备案与机构记录并存

同一目标T分别有客户申报P1、备案查询P2、机构拟识别P1的合成记录。它们保留各自产生目的、来源类别和工作状态，不能通过“术语统一”一键覆盖。差异核对是业务活动，不能仅看标签相同即视为已完成核实。[L2]

### 7.3 后续生产所需而本次不冒充完成的字段

真实认定记录还需适用制度与版本、产生机构、业务时点、知识截止、事实快照、选入与排除依据、证据定位、限制、复核和最终批准记录。状态按知识、业务有效性和工作进展分别表达。

本样板不自动建立真实人员签名或审批状态。未来扩展认定流程时，应保留这些合同，不把候选命中直接改写成“已确认”。

## 8. “7+1”在本样板中的完整落点

下表是本册的金融具化，不是原书案例。原项及绑定标准在第二册按来源保留。[S1]

| 业务分层约束 | 自然人／组织、持有人类型、结果主体要求 | 声明公理、约束文件和应用检查；完整推理未执行 |

### 10.2 运行方式

进入参考工程目录后，在可安装依赖的环境执行以下命令。Python（编程语言）建议3.11至3.13；本轮实测3.13.5，其他版本没有在本轮逐一验证。

```bash
python -m pip install -r requirements.txt
python run.py
```

基础命令只依赖RDFLib（RDF处理库）7.5.0和jsonschema（JSON模式校验库）4.26.0及其依赖。运行结果写入报告目录，不访问网络，不修改外部数据，不发布业务结论。

标准约束补验单独执行：

```bash
python -m pip install -r requirements-shacl.txt
python validate_shacl.py
```

该入口使用pySHACL（Python形状约束验证库），以关闭隐式推理、关闭外部导入、开启约束元校验的配置运行正例和“E1缺持有人”负例，并核对目标覆盖及指定违规。当前环境因网络名称解析失败未安装依赖，实际返回退出码2并输出“未执行”，没有改用自写验证器冒充。

### 10.4 反例覆盖与可反驳性

反例覆盖重复证据、少数与多数来源冲突、不同有效区间、迟到更正、迟到采信、未知与开放终止、缺比例、数值尺度、非有限数字、门槛舍入、多路径、循环、残余权益、缺覆盖声明、同名主体、位置身份冲突、错误更正身份、法人控制人、自动兜底禁止、零目标、缺持有人、字节与图等价、重复标识、输入不可变及无关问题局部阻塞。

其中三项基础合同先对空实现运行，观察到预期失败后实现；随后增加三项边界用例，发现原值尺度、替代身份、采信时间三个问题，修复后回归41项全部通过。失败记录保留为研发证据，不当作当前版本仍有失败。

这不是模型提供商对照试验，也不是完整监管覆盖证明。其价值是使本样板的关键承诺能够被明确检查、出现错误时能够定位，而不是只能阅读说明文字。

## 11. 从该样板扩展到下一场景

新场景应先明确新的能力问题，再判断现有主体、来源断言、时间、采信视图和结果记录是否含义一致。只新增真实差异，不要求导入全部受益所有人业务规则。

接真实数据时，先替换来源模式及身份映射，保留合成回归；新增控制算法时，单独声明控制机制、证据与人工裁定边界；接ECP（企业认知平台）时，按其实际配置生成专用资产并取得真实编译结果，不把本工程的通用文件直接视为已可导入。

发布前补齐独立业务复核、标准约束验证、所需逻辑推理检查、敏感数据与再分发许可检查。未完成这些步骤时，名称仍为参考候选，不提升为生产标准样板。
