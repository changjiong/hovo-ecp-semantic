# 交互与不确定性处理规范

## 目标

让 `hovo-ecp-semantic` 默认成为可自主推进的语义资产生产技能，而不是无限访谈工具。

核心原则：**能从证据得到的，不问；能低风险假设推进的，不问；只在高影响且不可可靠推断的决策处问；缺输入时局部阻塞，不全局停工。**

## 默认工作模式

### Autonomous（自主编写，默认）

先读取当前对话、附件、ECP Authoring Kit（编写工具箱）、已有语义资产、Schema（模式）、代码和可访问工具。只在一次 Decision Gate（决策门禁）集中处理真正的 `OPEN` 项。

### Review Gate（评审门禁）

先形成推荐模型、假设和待决策项，再一次性交用户复核。适合高价值领域模型评审。

### Workshop（研讨）

仅当用户明确要求“访谈、研讨、逐项挑战、把模型讨论透”时启用。可以使用 Design Tree（设计树）和 Frontier（当前可决策前沿）多轮展开。不得因普通资产生成请求自行进入 Workshop。

## 不确定性五态

| 状态 | 定义 | 行为 |
|---|---|---|
| `CONFIRMED` | 有明确权威来源 | 直接使用并记录来源 |
| `INFERRED` | 可由已有证据高置信推出 | 继续执行，记录推定依据 |
| `ASSUMED` | 可逆、低风险设计选择 | 采用推荐默认，写入 assumptions |
| `OPEN` | 高影响且无法可靠推断 | 进入 Decision Gate |
| `BLOCKED` | 缺少合法资产必需输入 | 只阻塞该资产及下游 |

## 澄清预算

默认：

- 主动澄清：最多 **1 轮**；
- 每轮：最多 **5 个问题**；
- 只允许询问 `OPEN`；
- 第二轮及以上只有用户明确进入 Workshop 才允许。

同一轮必须一次性给出问题、为什么它会改变语义结构、推荐答案和默认方案。不要逐题盘问。

## 事实与决策的职责边界

以下属于技能责任，不得询问用户代查：

- ECP Profile（配置边界）是否支持某构造；
- 用户附件中已经存在的字段、规范、IRI（国际化资源标识符）或资产信息；
- 可通过连接工具、代码库、Schema 或规范直接核实的事实。

以下只有在无法从业务证据推断且影响重大时才成为 `OPEN`：

- 核心概念身份标准；
- 两种互斥的业务语义承诺；
- 会导致已发布资产语义破坏的建模选择；
- 业务规则阈值本身属于组织决策而非外部事实。

## 局部阻塞

建立 Asset Dependency Graph（资产依赖图）。例如真实数据库 Schema 缺失：

```text
Ontology / CQ / 概念模型 -> 继续
SHACL 草案             -> 可继续（若不依赖物理字段）
Mapping                -> BLOCKED
Workspace Release 包    -> 被 Mapping 或其他必需资产阻塞
```

禁止把一个 `BLOCKED` 输入升级成整个任务停止。

## 假设策略

`ASSUMED` 必须满足：

1. 可逆；
2. 不伪造业务事实；
3. 不改变 ECP Profile 硬约束；
4. 不产生发布完成声明；
5. 在报告中明确列出。

## 决策门禁输出格式

当存在 `OPEN` 时，一次性输出最多五项：

```text
D1. 决策：<问题>
影响：<为什么会影响模型或资产>
推荐：<推荐方案 + 理由>
默认：<若用户不指定，是否允许采用默认；若不允许则说明阻塞范围>
```

用户确认后继续。不得在默认模式中重复进入第二轮。
